# 网页无限工厂开发验收

## 目标

沿用 Godot / GDScript 与现有贴图，实际导出浏览器版本。无限种子地图按需生成，开放区域从居中 32×32 起，每侧每次增加 8 格。产品送到研究站形成可消费库存；研究与扩张消耗库存但保留累计交付。新质数阶段需要额外扩张 3、5、8、12 次，后续温和增长，并由玩家主动研究。

物流科技必须在质数 7 开放后。首次提供 2 个建筑额度，此后每次扩张或科技提供 1 个额度；共享物流库存与研究库存分开，所有物流输入输出经过传送带并限速。

## 实现次序

1. 独立成长模型：费用确定性生成、永久交付、库存支付、科技、额度与版本化存档。
2. 种子分块世界：负坐标、固定矿点描述、保证起始与阶段资源、规则方形边界。
3. 接入原有固定步长模拟和界面，保留运输与乘法回归测试。
4. 物流站：8 个外围端口、方向识别、每口 3 个/秒、整站合计 6 个/秒、全局原子库存预留。
5. 内置中文字体、浏览器持久化与恢复、单线程 Web 导出和本地服务。
6. 浏览器实际操作、完整成长循环、两个视口和保存恢复验证。

### 完整成长的验证方式

`tools/test.ps1 -FullGrowth` 先运行普通回归，再运行规划器回归、从新世界开始的 `growth_test.gd` 和 `checkpoint_test.gd`。铺线器仅存在于测试目录，正式 Web 导出排除整个测试目录；它操作正常矿点、机器、传送带和拆除，不直接注入库存。

完整成长保存每次真实支付后的检查点。最终检查点测试以当前代码读回全部状态、比较继续模拟的一致性，再重新铺线让真实 2×3 产品经过两座共享物流站进入研究站，并测试堵塞入库与实际文件恢复。

本次完整成长与检查点脚本分别实际执行。`checkpoint_test.gd` 退出 0，41 项断言无失败：读回 496×496 的已成长世界并逐字段比较，在恢复后继续模拟仍一致；随后使用已获得的额度建两站，真实采矿交付至少 10 个额外的 6，阻断输出后共享库存继续增长，保存并读回的银行、研究库存、端口、在途物料、额度与暂停状态完全一致。最终检查点保存在 `qa/growth_checkpoint.json`，带实际物流链的额外检查点为 `qa/full-cycle-logistics.json`。

完整成长测试与浏览器操作是两类证据：浏览器手工走通开局至质数 5、网页存档及交互；较长的 5/7/11/13 连续成长在同一 Godot 模拟代码的无界面实例中真实采矿运行，不声称已经在浏览器中手工重复整段长流程。

### 已知边界

面向桌面鼠标键盘和 WebGL 浏览器，不包含移动端、多人与云存档。网页存档绑定浏览器和网站来源，隐私模式或清理网站数据可能删除存档。产品上限为 999999；地图没有预设关卡边界，但实际规模受内存、设备数量和坐标类型限制。质数 13 之后的长期经济平衡与超大规模性能不以本轮初版验收宣称已验证。
