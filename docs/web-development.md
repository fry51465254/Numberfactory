# 网页无限工厂开发验收

## 目标

沿用 Godot / GDScript 与现有贴图，实际导出浏览器版本。无限种子地图按需生成，开放区域从居中 32×32 起，每侧每次增加 8 格。产品送到研究站形成可消费库存；研究与扩张消耗库存但保留累计交付。新质数阶段需要额外扩张 3、5、8、12 次，后续温和增长，并由玩家主动研究。

物流科技必须在质数 7 开放后。首次提供 2 个建筑额度，此后每次扩张或科技提供 1 个额度；共享物流库存与研究库存分开，所有物流输入输出经过传送带并限速。

## 实现次序

1. 独立成长模型：费用确定性生成、永久交付、库存支付、科技、额度与版本化存档。
2. 种子分块世界：负坐标、固定矿点描述、保证起始与阶段资源、规则方形边界。
3. 接入原有固定步长模拟和界面，保留运输与乘法回归测试。
4. 物流站：8 个外围端口、方向识别、每口 3 个/秒、整站合计 6 个/秒、全局原子库存预留。
5. 内置中文字体、浏览器持久化与恢复、单线程 Web 导出和本地服务。
6. 浏览器实际操作、完整成长循环、两个视口和保存恢复验证。

### 已知边界

面向桌面鼠标键盘和 WebGL 浏览器，不包含移动端、多人与云存档。网页存档绑定浏览器和网站来源，隐私模式或清理网站数据可能删除存档。产品上限为 999999；地图没有预设关卡边界，但实际规模受内存、设备数量和坐标类型限制。质数 13 之后的长期经济平衡与超大规模性能不以本轮初版验收宣称已验证。

## 2026-10-12 首格弯带与四向乘法机

- 矿点识别改为验证相邻带的入口边，而非只验证其出口方向；八个外围出口都支持第一格立即左转或右转。活动矿点筛选也读取入口边，避免弯带已连接却不激活矿点。总产量、单口限速、共享轮询和地下分层不变。
- 乘法机按相邻传送带四向识别输入与输出，最多绑定两个输入方向，每侧一个原料缓存。已绑定线路保持稳定，多余输入停留在带上并显示原因；带有缓存的端口拆线后保持原料绑定，消耗后才可复用。输出按连接轮询，一侧堵塞可以选择另一侧；输出弯带及地下通道均可用。无传送带的旧设备直连保留兼容规则。
- 端口方向绑定、输出轮询和物料实际来向随存档保存。旧乘法机缓存按原端口恢复，加工周期、乘积范围、输出缓存和分阶段物料转移不变。将传送带的建造入口与动画来向分开，侧向合流不再改掉弯带形状、矿点接口或设备出口识别。
- 拖带首格推迟到首次有效移动时确定方向，过滤微小按下抖动；快速移动按网格穿越轨迹补格，取消固定先横后竖的走法；仅松手吸附临近输入，经过设备不再中途改道。沿本次路径回拖可撤回新带并恢复旧带几何，旧带物料不回滚；撤除已进入新带的物料按拆除计入清空记录。完整撤回不留起点或新地下段。
